# Принятые решения (ADR, кратко)

Формат: решение — почему — последствия. Новые решения добавляются в конец.

### D1. Один exe, CLI + служба, без отдельных процессов
Почему: пользователь ставит одну программу; служба и CLI делят код и файлы.
Последствия: межпроцессные блокировки (`.lock`, `.state.lock`) обязательны.

### D2. Источник правды о стратегии — служба `zapret` и значение реестра service.bat
Почему: пользователь может переставить стратегию через `service.bat`; менеджер это принимает.
Последствия: `currentInstall` читает реестр, state.json — только запасной вариант.

### D3. Проверка «настоящими запросами» на сыром TCP/TLS, а не через http.Client
Почему: нужна фаза сбоя (DNS / connect / TLS / заморозка 16–20 КБ), чтобы понять, что режет DPI;
системный прокси обходится намеренно.
Последствия: свой разбор HTTP/1.1 через `http.ReadResponse`; QUIC/UDP не проверяются.

### D4. Пакет main + чистые `internal/*` (2026-11), без Clean Architecture
Почему: ~4,5 тыс. строк; оркестрация завязана на SCM/WinDivert и одна. Вынесены только парсеры
недоверенных данных — их можно тестировать и fuzz-ить без Windows-API. Интерфейсы над SCM
ради моков не вводились: единственная реализация, а моки проверяли бы сами себя.
Последствия: SCM-логика проверяется вручную (TESTING_GUIDE); при росте — вынести `winsvc`
за интерфейс.

### D5. Корневая папка закрыта на запись для не-администраторов (2026-11)
Почему: наследование от `C:\` давало «Прошедшие проверку: изменение» → подмена бинарника
службы LocalSystem (CWE-732). Владелец меняется на «Администраторы»: иначе пользователь,
заранее создавший папку, вернул бы себе права.
Последствия: `install` отказывается работать в папке с чужими файлами; свои стратегии в
`custom\` и правка `config.json` — только с правами администратора; `check` без админа не
сохраняет результат в state.json.

### D6. Без новых зависимостей
Почему: каждая зависимость службы LocalSystem — поверхность атаки цепочки поставок.
Только стандартная библиотека и `golang.org/x/sys`. Инструменты (линтеры) — в CI через
`go run …@версия`, не в go.mod.

### D7. Toolchain закреплён (`toolchain go1.26.10`)
Почему: govulncheck нашёл 23 достижимые уязвимости stdlib в go1.26.1.
Последствия: `GOTOOLCHAIN=auto` скачивает нужную версию; обновление — через Dependabot/руками.

### D8. Загрузки: 3 попытки, 2 с × 2ⁿ + джиттер, повтор только 408/425/429/5xx и сетевых ошибок
Почему: GitHub отвечает 429/5xx при перегрузке; 404/403 не исправятся повтором.

### D9. MCP-серверы не подключены
Почему: проекту не нужны БД, браузер или внешние API; агенту хватает файловой системы,
go-инструментов и `gh`. Каждый MCP — лишние права и канал prompt injection.
Пересмотреть, если появится, например, трекер задач.

### D10. Инструкции агентов — один AGENTS.md
Почему: Codex, Cursor, Copilot, Gemini CLI читают AGENTS.md; Claude Code импортирует его
из CLAUDE.md (`@AGENTS.md`). Отдельные `.cursor/rules`, `copilot-instructions.md` устарели бы.

### D11. Интерфейс для двойного клика — консольное меню, а не окно (2026-11)
Почему: окно на чистом Win32 без зависимостей — ~1–1,5 тыс. строк unsafe-кода плюс манифест
для визуальных стилей и мелькание консоли при запуске; GUI-библиотеки противоречат D6.
Меню — тонкий слой: каждый пункт вызывает команду из таблицы `commands`, своей логики
изменения системы у него нет, поэтому меню и CLI не расходятся.
Последствия: UAC спрашивается один раз на всё меню (`cmdMenu` → `runElevated`); при отказе
меню работает без прав, а пункты с `admin: true` открываются отдельным окном, как в CLI.
Ввод ограничен цифрами и Enter; EOF никогда не выполняет действие.

### D12. Раздача exe — GitHub Releases по тегу, с аттестацией сборки (2026-11)
Почему: пользователю нужен готовый exe по постоянной ссылке. Релиз создаёт предустановленный
`gh`, а не стороннее action (меньше цепочка поставок); единственное новое action —
`actions/attest-build-provenance`, закреплённое по SHA. Подписи кодом нет (сертификат
платный), поэтому подлинность проверяется аттестацией и SHA-256.
Последствия: версия exe берётся из тега (`-X main.appVersion`); SmartScreen предупреждает
о неизвестном издателе — это описано в README и в тексте релиза.
