# Итоговый отчёт об инженерной доработке

Дата: 2026-11-08. База: `479e9d7`. Изменения — в рабочем дереве (не закоммичены).

## 1. Исходное состояние

Работающая утилита/служба для Windows на Go (≈ 4 000 строк, один пакет `main`), README,
23 теста (покрытие 16,4 %), без CI, линтеров и сканеров. Подробно —
[REPOSITORY_AUDIT.md](REPOSITORY_AUDIT.md).

## 3. Исправленные проблемы

- HIGH: 1 из 1.
- MEDIUM: 7 из 9 полностью; ARC-01 — частично (парсеры выделены, оркестрация осталась без
  абстракции SCM); TD-10 (оркестрация без автотестов) — не исправлено, см. §12.
- LOW: 24 из 27. Остались TD-11 (SCM без context), TD-13 (версия правится руками),
  TD-14 (race detector не прогнан локально — нет gcc; выполняется в CI).
- INFO: 3 исправлено (NET-04, NET-07, TD-05), остальные — ограничения или принятые решения.

## 4. Изменения архитектуры

- Новые пакеты `internal/batch`, `hostsfile`, `safezip`, `version`, `zapretfmt`, `textutil` —
  чистые функции над недоверенными данными, без `x/sys/windows`. Обоснование: граница доверия,
  fuzz-тестирование, независимость от Windows-API (D4).
- Решения выделены в чистые функции: `summarize` (здоров/нет сети/DNS), `releaseIsWorse` (откат).
- `downloader` вместо глобального клиента с жёсткими адресами; адреса GitHub подменяемы в тестах.
- Не делалось (сознательно): Clean Architecture, интерфейсы над SCM, `cmd/`, метрики — §ARCHITECTURE.

## 5. Изменения Go-кода

- Toolchain go1.26.1 → go1.26.10.
- Межпроцессная блокировка `state.json` (`.state.lock`), уникальные временные файлы + `Sync`.
- `errors.Join`, `errors.AsType`, `wg.Go`, `strings.SplitSeq`, `for range N`; удалён мёртвый код.
- Паника сторожа — в журнал со стеком (поведение «упасть и перезапуститься» сохранено).
- Сигнатуры: `updateRelease` → `error`; `startService(name)`; `checkTarget(…, roots)`;
  `migrateUserFiles` → `error`; `enableTCPTimestamps` → `error`.
- Восстановлена кодировка `manager_test.go`.

## 6. Сетевые компоненты

Загрузка релиза потоком в файл; повторы только временных ошибок с экспоненциальной паузой и
джиттером; https-only редиректы; лимиты на каждый ответ; дочитывание тела не-200; TLS ≥ 1.2;
отмена в паузах; ≤ 50 адресов проверки. Пробы доступности не менялись по поведению
(только `sleepCtx` вместо `time.Sleep`).

## 7. Исправления безопасности

ACL + владелец корневой папки (`secureTree`, проверка при старте службы, `doctor`); отказ
`install` в папку с чужими файлами; `netsh` и hosts — через системные пути; валидация
`repo`/`branch`/`targets`; безопасная распаковка с лимитами и проверкой имён Win32;
`asciiLower` против паники; строгий разбор событий журнала; согласованное удаление блока hosts;
обязательная копия hosts; защита испорченного state.json.

## 12. Оставшиеся проблемы

1. Оркестрация (подбор, починка, SCM, цикл службы) без автотестов — требует прав администратора и WinDivert (TD-10).
2. Целостность релиза держится только на TLS GitHub — нет сверки SHA-256 (SEC-12/TD-12).
3. Остановка службы посреди подбора может занять > 25 с (TD-11).
4. Сценарии с правами администратора и CI не прогнаны в этой сессии (§9).

## 13. Рекомендации

1. Прогнать вручную сценарий из TESTING_GUIDE с правами администратора: `install` → `doctor`
   («права … только у администраторов») → `select --dry-run` → `off 1` → `on` → `status`.
2. Опубликовать репозиторий/добавить remote и дождаться зелёного CI (race, fuzz, govulncheck).
3. Сверка SHA-256 релиза по `assets[].digest` GitHub API.
4. Прокинуть `context` в `stopService`/`startService`.
5. Стамповать версию `-ldflags -X main.appVersion=$(git describe)` в CI.
6. Скачивать релиз в CI и задавать `ZAPRET_TEST_DIR`, чтобы `TestRealStrategies` ловил изменения формата `.bat` у Flowseal.
