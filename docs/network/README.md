# Сетевое поведение

Аудит и найденные проблемы — [docs/engineering/NETWORK_AUDIT.md](../engineering/NETWORK_AUDIT.md).

Программа — только клиент: портов не слушает, входящих соединений нет.

## 1. Проверка доступности (health.go)

Цель — понять, режет ли DPI соединение, и на какой фазе.

| Параметр | Значение | Почему |
|---|---|---|
| Протокол | TCP → TLS 1.2+ (ALPN `http/1.1`) → `GET` HTTP/1.1, `Connection: close` | фаза сбоя видна; HTTP/2 и QUIC не нужны |
| Прокси | не используется | проверяется прямой путь, по которому идёт zapret |
| DNS | системный резолвер, отдельно, на весь бюджет; при `dns` — один повтор через 0,5 с | VPN с перехватом DNS отвечает медленно |
| Адреса | IPv4 первыми, не больше двух попыток соединения | бюджет времени |
| Таймауты | на адрес: 8 с (проверка), 6 с (подбор); connect ≤ min(timeout/2, 4 с); deadline на соединение | |
| Тело | читается до 48 КБ | ТСПУ «замораживает» TLS после 16–20 КБ |
| Успех | любой HTTP-ответ, включая 4xx/5xx | проверяется путь, а не сервис |
| Параллельность | по горутине на адрес, адресов ≤ 50 | 12 адресов по умолчанию |

Классификация (`classifyErr`): `dns`, `cert` (подмена/заглушка), `connect`, `refused`,
`reset` (RST/EOF — DPI), `tls-timeout`, `tls`, `no-response`, `freeze` (заморозка тела),
`http`, `bad-url`.

Сводка (`summarize`): нет интернета — не открылся ни один адрес группы `control`
(ya.ru, vk.com — в list-exclude, zapret их не трогает); проблема DNS — ≥ половины неудач
`dns`/`cert`; здоров — в каждой группе, кроме `control`, открылась доля ≥ `healthy_ratio`.

## 2. Загрузки (release.go, `downloader`)

| Параметр | Значение |
|---|---|
| Клиент | один `http.Client` на процесс (пул: 4 idle, keep-alive 30 с, idle 90 с) |
| TLS | ≥ 1.2, системные корневые сертификаты |
| Таймауты | dial 15 с, TLS 15 с, заголовки 30 с, весь запрос 3 мин |
| Прокси | `HTTPS_PROXY`/`HTTP_PROXY` из окружения |
| Редиректы | ≤ 10, только https |
| Повторы | 3 попытки; пауза 2 с × 2ⁿ⁻¹ + джиттер до 1 с; повтор: сетевые ошибки, 408, 425, 429, 5xx; без повтора: прочие 4xx, превышение лимита, отмена |
| Лимиты | version.txt 256 Б; hosts 1 МБ; список 4 МБ; ipset 32 МБ; zip 100 МБ (поток в файл) |
| Кэш CDN | к адресам raw.githubusercontent.com добавляется `?t=<unix>` |

Источники: `https://raw.githubusercontent.com/<repo>/<branch>/…` и
`https://github.com/<repo>/releases/download/<ver>/zapret-discord-youtube-<ver>.zip`;
`repo`/`branch` проверяются регулярными выражениями.

## 3. Влияние на систему

- Служба `zapret` (winws + WinDivert) перехватывает трафик по спискам/ipset стратегии.
- `netsh interface tcp set global timestamps=enabled` — нужно стратегиям с `fooling=ts`.
- `DnsFlushResolverCache` после изменения hosts.
- Подбор перебирает стратегии: на 1–3 минуты Discord, YouTube и включённые сайты «мигают».

## Диагностика сети

```powershell
zapret-manager check -v      # фаза сбоя и текст ошибки по каждому адресу
zapret-manager doctor        # конфликты: VPN-туннели, прокси, DoH, другие обходы
zapret-manager log 100       # журнал сторожа
```

| Симптом в `check -v` | Вероятная причина | Что делать |
|---|---|---|
| все `connect`, control тоже | нет интернета | сторож ничего не трогает |
| `dns` / `cert` | подмена DNS провайдером | включить DNS-over-HTTPS |
| `reset` / `tls-timeout` | DPI режет ClientHello | `select` |
| `freeze` | заморозка после 16–20 КБ | `select` (стратегии с fake/split) |
| работает только через VPN | трафик идёт в туннель | ожидаемо: zapret не участвует |
