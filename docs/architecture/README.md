## Компоненты

| Компонент | Файлы | Ответственность |
|---|---|---|
| CLI | `main.go` | разбор аргументов, UAC, вывод; каждая команда — функция `cmdX` |
| Служба | `watchdog.go` | `svc.Handler`, главный цикл, сон/пробуждение, пауза |
| Оркестрация | `engine.go` | решения: установка стратегии с откатом, подбор, самопочинка, обновление с откатом |
| Проверка | `health.go` | пробы TCP/TLS/HTTP, классификация сбоев, сводка (healthy / network down / DNS) |
| Обновления | `release.go`, `hosts.go` | загрузчик, версии, релизы, ipset, списки, hosts |
| Стратегии | `strategy.go` | перечень `.bat`, поиск по имени, командная строка winws, файлы настроек zapret |
| Безопасность ФС | `security.go` | ACL корневой папки, проверка «своя ли папка» |
| Система | `winsys.go` | SCM, реестр, процессы, Job Object, netsh, консоль, UAC |
| Диагностика | `doctor.go` | конфликты (GoodbyeDPI, Killer, AdGuard, VPN, прокси, DoH, права) |
| Конфиг/состояние | `app.go` | Config + валидация, State, блокировки, лог |
| Парсеры | `internal/{batch,hostsfile,safezip,version,zapretfmt,textutil}` | чистые функции над недоверенными данными |

## Почему так (кратко)

- Один пакет `main` для оркестрации: ~4 тыс. строк, одна реализация каждой системной
  операции. Интерфейсы ради моков не вводились (D4).
- Всё, что разбирает внешние данные, вынесено в `internal/` и покрыто fuzz-тестами:
  это граница доверия, и там нашлись реальные ошибки (паника на CP1251).
- Нет сети между компонентами: CLI и служба общаются через файлы (`state.json`, лог) и
  файловые блокировки.

## Модель исполнения и конкурентность

- **Служба:** горутина `Execute` обрабатывает команды SCM; горутина `watchdog` — единственная,
  кто трогает `App` в процессе службы. Остановка: `cancel()` + ожидание до 25 с.
- **Проверка:** `runHealthWith` — по горутине на адрес (≤ 50, `maxTargets`), `sync.WaitGroup`,
  у каждой свой `context.WithTimeout`; результаты пишутся в свой индекс слайса.
- **Тестовый winws:** процесс в Job Object с `KILL_ON_JOB_CLOSE`; две горутины — чтение вывода
  (до закрытия пайпа) и `Wait`. Обе завершаются вместе с процессом.
- **Межпроцессно:** `.lock` (долгие операции; служба при занятости пропускает цикл),
  `.state.lock` (короткое чтение-изменение-запись state.json). Файлы открываются без общего
  доступа; при падении процесса Windows закрывает дескриптор — «зависших» блокировок нет.

## Жизненный цикл службы

```
StartPending → Running ─┬─ каждые 30 с: ensureRunning (служба zapret жива?)
                        ├─ каждые check_interval_sec: periodicCheck → heal
                        ├─ каждые update_interval_hours: updateAll
                        ├─ PowerEvent resume: проверка через 20 с
                        └─ Stop/Shutdown → StopPending → cancel → ≤ 25 с → Stopped
паника в watchdog → лог со стеком → выход с кодом 1 → SCM перезапуск (10 с / 30 с / 2 мин)
```

## Самопочинка (heal)

1. DNS/сертификат — смена стратегии не поможет: событие с советом включить DoH, раз в час.
2. Перезапуск службы zapret → проверка через 3 с.
3. Подбор: сначала текущая + 4 лучших из прошлого подбора, затем все стратегии; тройка лидеров
   перепроверяется, берётся худший из двух замеров.
4. Ничего не работает — проверка новой версии zapret.
5. Подборы подряд без результата — интервал растёт: 30 мин → 1 ч → 2 ч → 4 ч (`HealStreak`).

## Обновление релиза

version.txt → (не новее / в BadVersions → стоп) → zip потоком в `tmp\` → `safezip.Extract` в
`<версия>.new` → проверка `validRelease` → rename → перенос `*-user.txt`, game filter, режима
ipset → ipset/списки → та же стратегия → замер → не здорова → подбор → `releaseIsWorse` →
откат на старую папку и `BadVersions += версия`, иначе `pruneReleases`.
