# zapret-manager — правила для AI-агентов и разработчиков

Единственный источник правил для любых coding agents (Claude Code, Codex, Cursor,
Copilot, Gemini CLI, Aider и др.). `CLAUDE.md` импортирует этот файл; отдельных копий
правил нет. Подробности — в [docs/ai/](docs/ai/), здесь — то, что нужно знать всегда.

## Что это

Один exe для Windows: консольная утилита и служба-сторож для
[Flowseal/zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube).
Ставит zapret в службу, обновляет релиз/ipset/списки/hosts, проверяет Discord и YouTube
настоящими запросами и сам подбирает стратегию, когда они отваливаются.

- Go 1.26 (`toolchain go1.26.10` в go.mod), одна зависимость — `golang.org/x/sys`.
- Только Windows (SCM, реестр, ACL, WinDivert). Сборка под другие ОС не поддерживается.
- Служба `zapret-manager` работает от **LocalSystem**, служба `zapret` (winws.exe) — тоже.
  Любая ошибка в том, что попадает в их командную строку или папку, — повышение привилегий.

## Карта

| Путь | Что там |
|---|---|
| `main.go` | CLI: таблица команд, install/status/check/select/use/list/update/hosts/off/on/doctor/log/uninstall |
| `app.go` | Config (+валидация), State (+межпроцессная блокировка), блокировки, лог, файловые помощники |
| `engine.go` | бизнес-логика: текущая установка, смена стратегии с откатом, подбор, починка, обновление релиза |
| `watchdog.go` | служба: цикл проверок, пауза, автозапуск zapret |
| `health.go` | проверка адресов: TCP → TLS → HTTP, классификация сбоев, решение «здоров/нет сети/DNS» |
| `release.go` | HTTP-загрузчик с повторами, версии, скачивание/распаковка релиза, ipset и списки |
| `hosts.go` | запись hosts с копией в backups\ |
| `strategy.go` | стратегии (`general*.bat`, `custom\*.bat`), сборка командной строки winws |
| `security.go` | ACL корневой папки (только администраторы пишут) |
| `winsys.go` | SCM, реестр, процессы, тестовый winws в Job Object, UAC |
| `doctor.go` | диагностика конфликтов |
| `internal/batch` | разбор .bat → аргументы winws (чистые функции, fuzz) |
| `internal/hostsfile` | слияние блока hosts (идемпотентно, fuzz) |
| `internal/safezip` | безопасная распаковка zip (traversal, ADS, лимиты; fuzz) |
| `internal/version` | версии релизов |
| `internal/zapretfmt` | game filter, режимы ipset, проверка списков |
| `internal/textutil` | BOM, строки, нормализация |

Пакеты `internal/*` не импортируют `golang.org/x/sys/windows` и не делают ввода-вывода
(кроме `safezip`) — туда идёт разбор любых недоверенных данных.

## Команды

```powershell
go build ./...                          # сборка
go test -count=1 ./...                  # все тесты (без админа, без сети)
go vet ./...
powershell -ExecutionPolicy Bypass -File scripts\check.ps1   # полный quality gate = CI
build.cmd                               # тесты + dist\zapret-manager.exe
```

Дополнительно: `ZM_NET=1 go test -run TestNetworkUpdateFlow -v .` — сетевой прогон
обновлений с настоящего GitHub во временную папку; `ZAPRET_TEST_DIR=<релиз>` — сверка
разбора всех стратегий настоящего релиза. Race detector нужен cgo (gcc) — в CI он есть.

## Обязательные правила

1. **Не запускай команды, меняющие систему, без явного разрешения пользователя:**
   `install`, `select` (без `--dry-run`), `use`, `update`, `hosts`, `off`, `on`,
   `uninstall`, `sc stop/delete`, правку hosts, `netsh`. Безопасно: `version`, `status`,
   `check`, `list`, `log`, `help` — лучше с `--dir <временная папка>`.
2. **Всё, что попадает в binPath службы или в CreateProcess, проверяется.** Новые
   переменные в .bat — только через `batch.ExtractWinwsArgs` (неизвестная переменная —
   ошибка). Значения из файлов пользователя — только после валидации (как
   `zapretfmt.ValidatePortRanges`).
3. **Не ослабляй ACL корневой папки** (`security.go`) и не создавай файлы вне неё от
   имени службы. Системные программы — по абсолютному пути (`systemBinary`).
4. **Сеть:** таймауты обязательны; повторы — только временных ошибок, конечное число,
   с паузой и джиттером (`downloader`); лимит размера на каждый ответ; редиректы только https.
5. **Конкурентность между процессами:** долгие операции — под `App.withLock`; изменение
   state.json — только через `App.updateState` (функция внутри не вызывает updateState).
6. **Служба zapret никогда не остаётся со сломанной командной строкой** — `applyStrategy`
   откатывает binPath. У службы zapret нет recovery actions (они мешают подбору).
7. **hosts:** копия в backups\ перед каждой записью; только блок между маркерами;
   `hostsfile.Merge` идемпотентен — держи это свойство (есть fuzz-тест).
8. **Ошибки не глотаются молча.** `_ =` только для закрытия дескрипторов и best-effort
   операций с комментарием почему. Паника в стороже логируется со стеком — не добавляй
   `recover`, скрывающий причину.
9. **Без новых зависимостей** без обоснования в `docs/ai/DECISIONS.md`.
10. **Не придумывай API.** Сверяйся с исходниками `golang.org/x/sys` в module cache
    (`go env GOMODCACHE`) — часть констант там отсутствует (например, `FILE_DELETE_CHILD`).
11. **Не подавляй линтеры без причины:** `//nolint:имя // почему` или `// #nosec Gxxx -- почему`.
12. **Тексты для пользователя — по-русски**, как во всей программе. Идентификаторы — английские.

## Как вносить изменения

1. Прочитай этот файл и нужный документ из `docs/ai/` (карта модулей, инварианты, тесты).
2. Найди вызывающих (`grep -n "имя(" *.go internal/*/*.go`) и связанные тесты.
3. Сначала тест, воспроизводящий проблему (для парсеров — ещё и seed в fuzz-тест).
4. Минимальное изменение; новые парсеры недоверенных данных — в `internal/`.
5. `scripts\check.ps1` (или как минимум gofmt + vet + golangci-lint + go test).
6. Обнови документацию, если изменилось поведение, команды, конфиг или инварианты.
7. Отчёт: что изменено, какие команды запускались и их фактический результат.

**Готово**, когда: проект собирается, `go test ./...` и линтеры проходят, новое поведение
покрыто тестом, документация соответствует коду, системные изменения не выполнялись без
разрешения. Не утверждай, что проверка прошла, если команда не запускалась.
